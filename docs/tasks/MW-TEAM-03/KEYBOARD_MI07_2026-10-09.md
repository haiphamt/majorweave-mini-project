## Quan sát BODY và giới hạn công cụ
Đã tái hiện chính quan sát cũ tại Path detail: mở bằng Enter, Đóng active; Shift+Tab → activeElement BODY, insideDialog=false, :focus-visible=false, lặp3lần. Escape qua locator Đóng vẫn đóng và trả đúng opener.
Không thấy một nút/link của nội dung nền nhận focus trong các trace modal. BODY ở biên có thể là focus chuyển tới browser chrome; DOM evaluator không hỗ trợ document.hasFocus và không cho đọc browser chrome. Gửi phím tiếp vào body khi modal đang mở bị công cụ từ chối. Vì vậy chưa chứng minh focus lọt vào trang nền hoặc biết vòng phím tiếp theo; không ghi Pass cho giữ focus trong modal, cũng không tự kết luận lỗi sản phẩm chắc chắn.
Explore first Shift+Tab có lần trả chính DIALOG, nên không nhận mọi modal đều cùng hành vi. Cần Hải/người kiểm dùng bàn phím vật lý xác minh Chrome/Edge: last Tab→first, first Shift+Tab→last, không mất focus ra chrome hoặc background theo yêu cầu nhóm.

## Vị trí và đề xuất cho Hải
Component dùng chung: **src/components/ui.tsx:12–16**, Dialog. Effect dùng showModal/close và restore previous.focus; Escape qua onCancel. Không có handler Tab riêng; code hiện phụ thuộc vòng focus native của trình duyệt. Đây là cơ chế xác định từ code; chưa đủ chứng minh nguyên nhân BODY là lỗi effect.
Nếu nhóm yêu cầu vòng focus rõ ràng giữa first/last, đề xuất Hải thêm guard onKeyDown cho Tab tại dialog (không thay CSS hoặc feature):
1. Mỗi keydown lấy controls tabbable, enabled, visible trong dialog; loại hidden, tabindex=-1 và input hidden.
2. Shift+Tab khi active=first hoặc chính dialog: preventDefault, focus last.
3. Tab khi active=last hoặc chính dialog: preventDefault, focus first.
4. Không có control: preventDefault, focus dialog với tabIndex=-1.
5. Giữ native showModal/inert, onCancel Escape và restore opener; không chặn Tab ở nội bộ form/date.
Không áp dụng patch vào file chung trong lượt này. Sau patch cần kiểm lại disabled/filtered controls, modal có một control, native date, Escape và return focus bằng cả công cụ và bàn phím vật lý. Đây là đề xuất hardening để review, không phải patch đã kiểm thử hoặc root cause đã xác nhận.

Đoạn patch đề xuất trong Dialog, gửi Hải review (thêm handler và gắn onKeyDown; chưa thực thi):

```tsx
function guardTab(event: React.KeyboardEvent<HTMLDialogElement>) {
  if (event.key !== 'Tab') return;
  const dialog = event.currentTarget;
  const controls = Array.from(dialog.querySelectorAll<HTMLElement>(
    'a[href], button, input:not([type="hidden"]), select, textarea, [tabindex]'
  )).filter(element => element.tabIndex >= 0 &&
    !element.matches(':disabled') && element.getClientRects().length > 0 &&
    getComputedStyle(element).visibility !== 'hidden');
  const first = controls[0];
  const last = controls.at(-1);
  const active = document.activeElement;
  if (!first || !last) {
    event.preventDefault();
    dialog.focus();
  } else if (event.shiftKey && (active === first || active === dialog)) {
    event.preventDefault();
    last.focus();
  } else if (!event.shiftKey && (active === last || active === dialog)) {
    event.preventDefault();
    first.focus();
  }
}
// Giữ nguyên props/handlers hiện có, thêm trên <dialog>:
// tabIndex={-1} onKeyDown={guardTab}
```
Hải cần kiểm lựa chọn tabbable với radio group/contenteditable nếu thêm các loại control đó; không coi selector đề xuất là thư viện focus trap hoàn chỉnh.
