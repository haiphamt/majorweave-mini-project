SQ01 Đăng nhập Google và nhận phiên

Đối chiếu code ngày 11/10/2026 · EF38, EF39

Điều kiện và nhánh cần nhớ

  • Hình mô tả đường thành công ở mức thành phần; các HTTP redirect đi qua trình duyệt. Website không giữ Google Client Secret.
  • Trước khi bật Continue, UI kiểm tra /auth/v1/settings để xác nhận Google provider khả dụng. Không xin quyền Gmail/Drive; Google không cần SMTP/Resend. Email auth đang ẩn.
  • Hủy/access_denied hoặc lỗi mạng hiển thị thông báo an toàn, không giả báo đăng nhập. Có phiên chưa đồng nghĩa đã tải workspace; xem SQ02.
  • Phiên đã tồn tại được SDK khôi phục khi reload. Guest không phải Supabase Anonymous Auth.

Đọc các thông điệp

  1. CONTINUE — Người học chọn Continue with Google sau khi UI đã kiểm tra provider khả dụng.
  2. CHECK PENDING — prepareGoogleSignIn chặn chuyển trang nếu còn form/draft/candidate/preview/transfer.
  3. URL OAUTH — SDK signInWithOAuth tạo URL với callback origin và prompt chọn tài khoản; skipBrowserRedirect để UI tự chuyển trang.
  4. AUTHORIZE — SDK tạo URL OAuth; trình duyệt chuyển đến endpoint authorize của Supabase.
  5. REDIRECT — Supabase hướng trình duyệt sang Google.
  6. GOOGLE LOGIN — Trình duyệt mở màn hình Google.
  7. CHỌN TÀI KHOẢN — Người học tự chọn tài khoản/xác nhận quyền nếu Google hỏi.
  8. CALLBACK — Google trả kết quả đến Supabase Auth qua callback OAuth, với trình duyệt làm trung gian redirect.
  9. ĐỔI CODE — Supabase Auth xử lý việc đổi authorization code phía server.
  10. IDENTITY — Google trả nhận diện cơ bản theo scope của OAuth.
  11. APP CALLBACK — Supabase chuyển về origin ứng dụng; SDK xử lý phiên từ callback.
  12. PHIÊN SẴN — AuthProvider chờ khôi phục phiên trước HashRouter; AccountWorkspace chọn scope theo user ID.
